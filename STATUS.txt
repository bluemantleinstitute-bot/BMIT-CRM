Attack Scenarios:
  1. Malicious page performs hidden POST to /api/account/transfer-ownership
     to transfer account ownership away from the victim.
  2. Attacker revokes all API keys via DELETE /api/account/api-keys/[id].
  3. Attacker changes WhatsApp config via POST /api/whatsapp/config.
  4. Attacker sends messages or broadcasts on behalf of the victim.
  5. Attacker invites new members or escalates their own role.

Recommendation:
  1. Implement CSRF tokens (e.g., csrf-csrf library or double-submit
     cookie pattern).
  2. Add SameSite=Strict or SameSite=Lax to all auth cookies.
  3. Validate Origin/Referer headers as defense-in-depth.

H-3: CSP is Report-Only (No Enforcement)
--------------------------------------------------------------------------------
CWE         : CWE-693 — Protection Mechanism Failure
CVSS        : 6.1
Status      : OPEN
Effort      : 1 day

Description:
  File: next.config.ts, line 39
  key: "Content-Security-Policy-Report-Only"

  The Content-Security-Policy is set as Report-Only. Violations are
  logged but NOT blocked. Even if an XSS payload executes, CSP will
  not prevent it.

  Additionally, the CSP includes 'unsafe-inline' and 'unsafe-eval' in
  script-src (line 45), which significantly weakens any future
  enforcement.

  CSP Directives:
    default-src 'self'
    script-src 'self' 'unsafe-inline' 'unsafe-eval'     <-- WEAK
    style-src 'self' 'unsafe-inline'
    img-src 'self' data: blob: https:
    media-src 'self' blob: https://*.supabase.co
    font-src 'self' data:
    connect-src 'self' https://*.supabase.co wss://*.supabase.co
    frame-ancestors 'none'
    base-uri 'self'
    form-action 'self'

Recommendation:
  1. After validation period, flip to Content-Security-Policy.
  2. Migrate to nonce-based CSP to eliminate unsafe-inline.
  3. Remove unsafe-eval (no application code uses eval()).
